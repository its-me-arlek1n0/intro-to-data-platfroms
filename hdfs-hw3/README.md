# ДЗ 3 — автоматизированное развертывание Apache Hive и загрузка данных в партиционированную таблицу

В рамках домашнего задания реализовано и автоматизировано развертывание Apache Hive с возможностью одновременного подключения нескольких клиентов. Запускаются отдельные сервисы Hive Metastore и HiveServer2, а для хранения метаданных используется PostgreSQL.

Загрузка данных в партиционированную таблицу и проверка работы нескольких клиентов автоматизированы с помощью bash-скриптов. Все управляющие команды запускаются с edge-ноды `team-11-en`. Для хранения данных используется HDFS из первого ДЗ, для выполнения вычислительных заданий — YARN из второго ДЗ.

**Используемые версии:**

- Hive 4.0.0-alpha-2;
- Hadoop 3.4.2;
- Java 11;
- PostgreSQL 16.

## Архитектура кластера

| Узел | IP | Роль |
|---|---|---|
| `team-11-en` | `10.11.0.10` | Edge Node, PostgreSQL, Hive Metastore, HiveServer2, клиент Beeline |
| `team-11-nn` | `10.11.0.11` | NameNode, SecondaryNameNode, DataNode, ResourceManager, NodeManager, JobHistoryServer |
| `team-11-00` | `10.11.0.12` | DataNode, NodeManager |
| `team-11-01` | `10.11.0.13` | DataNode, NodeManager |

HiveServer2 принимает SQL-запросы клиентов и поддерживает несколько независимых сессий. Для подключения используется клиент Beeline и протокол JDBC.

Hive Metastore хранит сведения о базах, таблицах, столбцах, партициях и расположении файлов. Эти метаданные записываются в отдельную базу PostgreSQL `metastore`, а сами данные таблиц находятся в HDFS.

Embedded-подход не используется: Hive Metastore работает отдельным процессом, обращается к PostgreSQL и доступен HiveServer2 по Thrift.

| Сервис | Адрес | Назначение |
|---|---|---|
| PostgreSQL | `localhost:5432` на edge | Хранение метаданных Hive |
| Hive Metastore | `thrift://team-11-en:9083` | Доступ к метаданным |
| HiveServer2 | `jdbc:hive2://team-11-en:10000` | Подключение SQL-клиентов |
| HDFS | `hdfs://team-11-nn:8020` | Хранение файлов таблиц |

Для вычислительных запросов используется движок MapReduce, задания которого выполняются через YARN. Простое чтение строк с `LIMIT` может выполняться без запуска задания MapReduce.

# Назначение файлов

## `env.sh`

Содержит общие параметры установки и подключения:

- версию Hive и адрес архива;
- каталог установки Hive;
- путь к установленному Hadoop;
- каталог логов;
- адрес, порт, имя базы и учётные данные PostgreSQL;
- адрес JDBC-драйвера PostgreSQL;
- адрес и порт Hive Metastore;
- порт HiveServer2;
- каталог хранения таблиц в HDFS.

Также добавляет команды Hive и Hadoop в `PATH`.

Остальные скрипты подключают параметры командой:

```bash
source ./env.sh
```

По умолчанию Hive устанавливается в:

```text
~/opt/apache-hive-4.0.0-alpha-2-bin
```

Логи сохраняются в `~/hw3/logs`. Если проект размещается в другом каталоге, нужно изменить `HIVE_LOGS` в `env.sh`.

## `config/hive-site.xml`

Содержит шаблон конфигурации Hive:

- подключение к PostgreSQL;
- адрес Hive Metastore;
- параметры HiveServer2;
- каталог таблиц в HDFS;
- движок MapReduce и путь к дополнительной библиотеке.

Значения, зависящие от установки, указаны как переменные `${DB_HOST}`, `${METASTORE_HOST}`, `${HIVE_HOME}` и другие. Скрипт `scripts/01_install.sh` подставляет параметры из `env.sh` командой `envsubst` и записывает готовый файл в `$HIVE_HOME/conf/hive-site.xml`.

## `.gitignore`

Исключает создаваемый каталог `logs/` из добавления в Git.

## `sql/create_table.sql`

Создаёт базу `hw3` и таблицу `hw3.events`, если они ещё не существуют.

Таблица содержит следующие поля:

| Поле | Тип | Назначение |
|---|---|---|
| `user_id` | `INT` | Идентификатор пользователя |
| `event_type` | `STRING` | Тип события: просмотр, добавление в корзину, покупка или возврат |
| `product` | `STRING` | Название товара |
| `price` | `DOUBLE` | Цена |
| `dt` | `STRING` | Дата, по которой данные разделяются на партиции |

Параметры хранения задаются следующим образом:

```sql
PARTITIONED BY (dt STRING)
ROW FORMAT DELIMITED
FIELDS TERMINATED BY ','
STORED AS TEXTFILE;
```

Данные хранятся в текстовых файлах без заголовка, поля разделяются запятыми. В каждой строке файла находятся четыре поля: `user_id`, `event_type`, `product`, `price`. Значение `dt` задаётся при загрузке в конкретную партицию.

# `deploy_hive.sh` — скрипт автоматического развертывания Hive

Последовательно выполняет действия следующих скриптов:

```text
01_install.sh -> 02_start.sh -> 03_load_data.sh -> 04_check_clients.sh
```

Перед запуском нужны работающие HDFS и YARN из предыдущих ДЗ, Java 11 и настроенные команды Hadoop на edge. Пользователь `team` должен иметь доступ к HDFS и права `sudo` для установки и запуска PostgreSQL. Имена узлов должны разрешаться во внутренние IP-адреса.

Установка требует доступа к репозиториям пакетов, архиву Apache Hive и сайту загрузки JDBC-драйвера. Скрипты рассчитаны на Ubuntu с доступными командами `wget`, `tar`, `awk` и `pgrep`.

Код для запуска на edge, где файлы проекта размещены в `~/hw3`:

```bash
ssh team@111.88.130.12
cd ~/hw3

./deploy_hive.sh
```

При необходимости шаги можно выполнить отдельно:

```bash
bash scripts/01_install.sh
bash scripts/02_start.sh
bash scripts/03_load_data.sh
bash scripts/04_check_clients.sh
```

Полный запуск включает загрузку тестовых данных с заменой содержимого трёх партиций, описанных ниже.

Установка Hadoop и форматирование NameNode в третьем ДЗ не выполняются.

# `01_install.sh`

Скрипт устанавливает и подготавливает Hive на edge-ноде.

Он выполняет следующие действия:

1. создаёт каталоги установки и логов;
2. устанавливает PostgreSQL и пакет `gettext-base` с командой `envsubst`, запускает PostgreSQL;
3. создаёт пользователя `hive` и базу `metastore`, если они отсутствуют;
4. скачивает и распаковывает Hive 4.0.0-alpha-2, если каталог установки отсутствует;
5. устанавливает JDBC-драйвер PostgreSQL, если он ещё не установлен;
6. использует библиотеку Guava из Hadoop для согласования зависимостей;
7. проверяет наличие Commons Collections для заданий MapReduce;
8. подставляет параметры в шаблон `config/hive-site.xml` и устанавливает готовую конфигурацию;
9. подготавливает каталоги в HDFS;
10. проверяет схему метастора и при её отсутствии выполняет инициализацию через `schematool`.

PostgreSQL устанавливается из системного репозитория. На используемой учебной машине установлена версия 16.

Конфигурация Hive формируется из `config/hive-site.xml` с использованием параметров из `env.sh` и записывается в:

```text
~/opt/apache-hive-4.0.0-alpha-2-bin/conf/hive-site.xml
```

В ней задаются подключение к PostgreSQL, адрес Metastore, параметры HiveServer2, каталог таблиц и движок выполнения запросов. Например:

```xml
<property>
  <name>hive.metastore.uris</name>
  <value>thrift://team-11-en:9083</value>
</property>
<property>
  <name>hive.execution.engine</name>
  <value>mr</value>
</property>
```

Библиотека `commons-collections-3.2.2.jar` из дистрибутива Hive подключается через `hive.aux.jars.path`, чтобы она была доступна заданиям MapReduce.

HiveServer2 слушает порт `10000` на сетевых интерфейсах edge. Используется учебная конфигурация без проверки паролей (`hive.server2.authentication=NONE`), запросы выполняются от пользователя серверного процесса (`hive.server2.enable.doAs=false`).

В HDFS создаются каталог таблиц `/user/hive/warehouse` и временный каталог `/tmp`. Для warehouse добавляется право записи группе, для `/tmp` устанавливаются права `777`.

Инициализация схемы выполняется командой:

```bash
schematool -dbType postgres -initSchema
```

При последующих обычных запусках достаточно использовать `02_start.sh`. После изменения конфигурации уже работающие сервисы Hive нужно перезапустить, чтобы они прочитали новые настройки.

# `02_start.sh`

Скрипт запускает:

```text
Hive Metastore на team-11-en:9083
HiveServer2 на team-11-en:10000
```

Перед запуском каждого сервиса проверяет наличие его процесса. Повторно работающий сервис не запускается.

После запуска Metastore скрипт ожидает доступности порта `9083`. Затем запускает HiveServer2 и проверяет его готовность через Beeline запросом `SHOW DATABASES`.

Для запуска используется `nohup`, поэтому процессы продолжают работать после закрытия SSH-сессии. Автоматический запуск Hive после перезагрузки машины этими скриптами не настраивается.

Код для запуска:

```bash
cd ~/hw3
bash scripts/02_start.sh
```

PostgreSQL должен быть запущен заранее. Если после перезагрузки он остановлен:

```bash
sudo service postgresql start
```

# `03_load_data.sh`

Скрипт генерирует тестовые данные и загружает их в партиционированную таблицу `hw3.events`.

Он выполняет следующие действия:

1. создаёт временный локальный каталог;
2. генерирует три CSV-файла по 500 строк;
3. загружает файлы во временный каталог HDFS `/tmp/hw3_events`;
4. выполняет `sql/create_table.sql` через Beeline;
5. формирует и выполняет команды загрузки для каждой даты;
6. выводит список партиций и первые десять строк одной из них;
7. удаляет временный локальный каталог после успешного выполнения.

Создаются три партиции:

```text
dt=2024-01-01
dt=2024-01-02
dt=2024-01-03
```

Всего загружается 1500 строк. Файлы перемещаются из временного каталога HDFS в каталог таблицы командой:

```sql
LOAD DATA INPATH '/tmp/hw3_events/dt=2024-01-01/events_2024-01-01.csv'
OVERWRITE INTO TABLE hw3.events PARTITION (dt='2024-01-01');
```

`OVERWRITE` заменяет данные указанной партиции. Поэтому повторный запуск не добавляет дубли, но перезаписывает содержимое этих трёх партиций тестовыми данными.

Каталог таблицы в HDFS:

```text
/user/hive/warehouse/hw3.db/events
```

Внутри него данные распределяются по каталогам `dt=2024-01-01`, `dt=2024-01-02` и `dt=2024-01-03`.

Код для запуска:

```bash
cd ~/hw3
bash scripts/03_load_data.sh
```

# `04_check_clients.sh`

Скрипт проверяет одновременное использование Hive несколькими клиентами.

Он запускает три процесса Beeline в фоне. Каждый клиент создаёт отдельную сессию HiveServer2 и запрашивает пять строк из своей партиции:

```sql
SELECT * FROM hw3.events WHERE dt='2024-01-01' LIMIT 5;
```

После запуска всех клиентов скрипт ожидает завершения каждого процесса, проверяет код возврата и наличие пяти строк с ожидаемой датой в результате.

Код для запуска:

```bash
cd ~/hw3
bash scripts/04_check_clients.sh
```

Ожидаемый вывод:

```text
Проверка клиента 1: успешно, получено 5 строк
Проверка клиента 2: успешно, получено 5 строк
Проверка клиента 3: успешно, получено 5 строк
```

Вывод клиентов сохраняется в `logs/client_1.log`, `logs/client_2.log` и `logs/client_3.log`. Если хотя бы один запрос завершился с ошибкой или вернул неверное число строк, скрипт завершается с ненулевым кодом.

# `05_stop.sh`

Скрипт отправляет сигналы завершения процессам HiveServer2 и Hive Metastore. PostgreSQL и службы Hadoop продолжают работать, данные HDFS и метаданные PostgreSQL сохраняются.

Код для остановки:

```bash
cd ~/hw3
bash scripts/05_stop.sh
```

Остановка прерывает клиентские сессии, поэтому перед её выполнением нужно завершить работу с Hive.

Для последующего запуска используется:

```bash
bash scripts/02_start.sh
```

# Проверка вручную

Подключение выполняется на edge-ноде:

```bash
cd ~/hw3
source ./env.sh
beeline -u "jdbc:hive2://localhost:${HS2_PORT}"
```

Список партиций и чтение данных:

```sql
SHOW PARTITIONS hw3.events;
SELECT * FROM hw3.events WHERE dt='2024-01-02' LIMIT 10;
```

Проверка количества строк в каждой партиции:

```sql
SELECT dt, COUNT(*) FROM hw3.events GROUP BY dt;
```

Ожидаемый результат после загрузки:

```text
2024-01-01  500
2024-01-02  500
2024-01-03  500
```

Запрос с группировкой проверяет выполнение вычислений через MapReduce и YARN. История завершённых заданий доступна в JobHistoryServer из второго ДЗ.

С другого узла внутренней сети, где установлен клиент Beeline, подключение выполняется по адресу:

```bash
beeline -u "jdbc:hive2://team-11-en:10000"
```

Для проверки нескольких сессий вручную можно открыть несколько терминалов и подключиться из каждого к одному HiveServer2.

```text

```

Просмотр последних сообщений:

```bash
tail -n 50 ~/hw3/logs/metastore.log
```
