# ДЗ 5 — автоматизация обработки данных Spark на YARN с помощью Prefect

В рамках домашнего задания реализован поток Prefect, который запускает Apache Spark под управлением YARN, читает предварительно загруженные данные из HDFS, выполняет трансформации и сохраняет результат как таблицу Hive.

Подготовка данных, запуск потока и проверка результата автоматизированы с помощью bash-скриптов. Используется инфраструктура предыдущих заданий: HDFS из первого ДЗ, YARN из второго ДЗ, Hive Metastore и HiveServer2 из третьего ДЗ, установленный и настроенный Spark из четвёртого ДЗ. Все управляющие команды запускаются с edge-ноды `team-11-en`.

**Используемые версии:**

- Prefect 3.9.4;
- Spark 3.5.9, сборка для Hadoop 3;
- Hadoop 3.4.2;
- Hive 4.0.0-alpha-2;
- Java 11;
- Python 3.12.

## Архитектура кластера

| Узел | IP | Роль |
|---|---|---|
| `team-11-en` | `10.11.0.10` | Edge Node, поток Prefect, Spark driver, PostgreSQL, Hive Metastore, HiveServer2, клиент Beeline |
| `team-11-nn` | `10.11.0.11` | NameNode, SecondaryNameNode, DataNode, ResourceManager, NodeManager, JobHistoryServer |

Prefect управляет последовательностью задач и фиксирует их состояния. При используемом способе запуска автоматически поднимается временный локальный сервер Prefect, который останавливается после завершения потока.

Spark запускается в режиме `client`: драйвер работает на edge, а исполнители — в контейнерах YARN. HDFS хранит исходный CSV и файлы результата. Spark обращается к Hive Metastore для регистрации таблицы, после чего её можно прочитать через HiveServer2 клиентом Beeline.

| Сервис | Адрес | Назначение |

| Hive Metastore | `thrift://team-11-en:9083` | Хранение и получение описания таблицы |
| HiveServer2 | `jdbc:hive2://team-11-en:10000` | Выполнение проверочных SQL-запросов через Beeline |

Перед запуском нужны:

- работающие HDFS и YARN из первых двух ДЗ;

# `02_prepare_data.sh`

Скрипт создаёт тестовый CSV и предварительно загружает его в HDFS.

Он выполняет следующие действия:

1. создаёт временный локальный каталог;
2. генерирует CSV с заголовком;
3. создаёт входной каталог в HDFS;
4. загружает CSV с заменой одноимённого файла;
5. выводит информацию о файле и первые пять строк;
6. удаляет временный локальный каталог при завершении через `trap`.

Структура входных данных:

| Поле | Назначение |
|---|---|
| `event_id` | Идентификатор события |
| `user_id` | Идентификатор пользователя |
| `event_type` | Тип события: `view`, `cart`, `purchase`, `refund` |
| `product` | Название товара |
| `price` | Цена |
| `quantity` | Количество товара |
| `dt` | Дата события |

Для создания данных используется `random.seed()`, чтобы воспроизводить тестовый набор при повторном запуске в используемом окружении. Данные соодержаи информацию за 4 дня по 1000 событий на день.

Файл размещается в HDFS по пути:

```text
/user/team/hw5/input/events.csv
```

Код для запуска:

```bash
bash scripts/02_prepare_data.sh
```

# `03_run_flow.sh`

Скрипт запускает весь процесс обработки через Prefect.

Он выполняет следующие действия:

1. создаёт каталоги логов и отчётов;

Код для запуска:

```bash
bash scripts/03_run_flow.sh
```

# `flows/hw5_flow.py` — поток обработки данных

Поток называется `hw5-spark-etl`. Его задачи выполняются последовательно:

```text
check_hdfs_data -> submit_spark_job -> check_yarn_status -> verify_table
```

Идентификатор приложения, возвращённый `submit_spark_job`, передаётся в `check_yarn_status`. Ошибка задачи останавливает дальнейшее выполнение и переводит поток в состояние `Failed`.

## `check_hdfs_data`

Проверяет наличие конкретного непустого файла:

```bash
hdfs dfs -test -s /user/team/hw5/input/events.csv
```

Если файл отсутствует, пуст или недоступен, задача завершается ошибкой. Проверка выполняется до отправки Spark-приложения.

## `submit_spark_job`

Отправляет Spark-приложение в YARN командой:

```bash
spark-submit --master yarn --deploy-mode client app/spark_job.py
```

В самом потоке путь к Python-файлу формируется от каталога проекта. Вывод Spark сохраняется в `logs/spark_submit.log`. Из строки `YARN application ID: application_...` извлекается ID текущего запуска.

При ошибке `spark-submit` или отсутствии ID задача завершается ошибкой.

## `check_yarn_status`

Запрашивает состояние именно текущего приложения через:

```bash
yarn application -status application_1791754171539_0051
```

В команде используется ID, полученный от `submit_spark_job`; выше приведён пример контрольного запуска. Проверяются код завершения команды и поля `State` и `Final-State`. Успешным считается сочетание:

```text
State : FINISHED
Final-State : SUCCEEDED
```

Если приложение ещё работает, задача повторяет запрос. Предусмотрено до 15 попыток с паузами по две секунды. Время выполнения самих команд добавляется к паузам.

Состояния `FAILED` и `KILLED`, ошибка получения статуса или исчерпание попыток приводят к ошибке задачи.

## `verify_table`

Проверяет результат через клиент `$HIVE_HOME/bin/beeline`:

- наличие таблицы в базе `hw5`;
- список зарегистрированных партиций;
- чтение строк таблицы;
- агрегацию суммы по каждой дате.

Затем проверяет доступность каталога таблицы в HDFS. Ошибка SQL-запросов или команды просмотра HDFS приводит к ошибке задачи.

После успешного выполнения всех четырёх задач поток выводит:

```text
Поток обработки данных успешно завершён
```

# `app/spark_job.py` — обработка данных Spark

Приложение выполняется внутри задачи `submit_spark_job` и реализует вычислительную часть задания.

## Создание сессии и подключение к HDFS

Создаёт `SparkSession` с поддержкой Hive через `enableHiveSupport()`. Менеджер ресурсов YARN и режим `client` задаются при вызове `spark-submit`.

Приложение выводит фактические ID приложения и master, затем получает Hadoop FileSystem, проверяет существование входного пути и выводит URI HDFS.

## Чтение данных

CSV читается с заголовком и явной схемой. Поля `event_id` и `user_id` задаются целыми числами, остальные поля на этапе чтения — строками.

После чтения выводится количество исходных записей. Для подготовленного набора ожидается:

```text
Прочитано строк: 4000
```

## Трансформации

Приложение:

1. преобразует `price` в `double`, а `quantity` — в `int`;
2. оставляет строки с `price > 0` и `quantity > 0`;
3. вычисляет `amount = price * quantity` с округлением до двух знаков;
4. группирует события по `dt` и `event_type`;
5. рассчитывает агрегаты для каждой группы.

| Поле результата | Значение |
|---|---|
| `event_type` | Тип события |
| `events_cnt` | Число исходных событий в группе |
| `unique_users` | Число различных пользователей в группе |
| `total_amount` | Сумма стоимости событий с учётом количества товара |
| `avg_price` | Средняя цена исходных событий |
| `dt` | Дата, используемая как ключ партиционирования |

## Сохранение таблицы

Приложение создаёт базу `hw5`, если она отсутствует, и записывает результат:

```python
summary.write.mode("overwrite").partitionBy("dt").saveAsTable(
    f"{DB_NAME}.{TABLE_NAME}"
)
```

`overwrite` заменяет существующий результат, `partitionBy("dt")` разделяет данные по датам, `saveAsTable` сохраняет таблицу с регистрацией в Hive Metastore.

В проверенной конфигурации файлы записываются в формате Parquet. Итоговая таблица — `hw5.events_summary`, расположение в HDFS:

```text
/user/hive/warehouse/hw5.db/events_summary
```

Для четырёх дат создаются четыре каталога партиций. При текущем наборе данных каждая дата содержит четыре типа событий, поэтому в таблице 16 строк.

После записи приложение выводит результат и партиции, читает несколько строк сохранённой таблицы и завершает Spark-сессию.

# `04_check_table.sh`

Скрипт позволяет отдельно проверить уже созданную таблицу без повторного запуска всего потока.

Он выполняет через клиент Hive:

```sql
SHOW TABLES IN hw5;
SHOW PARTITIONS hw5.events_summary;
SELECT * FROM hw5.events_summary ORDER BY dt, event_type LIMIT 12;
SELECT dt, SUM(total_amount) AS day_amount
FROM hw5.events_summary GROUP BY dt ORDER BY dt;
```

Затем выводит содержимое каталога таблицы в HDFS. Вывод сохраняется в `reports/check-table.txt`.

Код для запуска:

```bash
bash scripts/04_check_table.sh
```

`LIMIT 12` ограничивает только показанную выборку. В итоговой таблице подготовленного набора находятся 16 строк.

# Проверка результата

Успешное выполнение подтверждается следующими признаками:

- четыре задачи Prefect и сам поток завершаются в `Completed`;
- master Spark — `yarn`;
- приложение YARN имеет состояния `FINISHED` и `SUCCEEDED`;
- прочитано 4000 строк из HDFS;
- таблица доступна через Hive и содержит четыре партиции;
- каталог результата существует в HDFS.

При необходимости проверить количество строк и исходных событий вручную:

```bash
cd ~/hw5
source ./env.sh
"$HIVE_HOME/bin/beeline" -u "jdbc:hive2://localhost:${HS2_PORT}"
```

```sql
SELECT COUNT(*) AS summary_rows, SUM(events_cnt) AS source_events
FROM hw5.events_summary;

SELECT dt, COUNT(*) AS groups_count, SUM(events_cnt) AS events_count
FROM hw5.events_summary
GROUP BY dt
ORDER BY dt;
```

Для подготовленного набора ожидаются 16 строк результата и 4000 исходных событий. На каждую дату приходятся четыре группы и 1000 событий.
