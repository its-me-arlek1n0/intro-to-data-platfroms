# ДЗ 1 — автоматизированное развертывание кластера HDFS

В рамках домашнего задания реализовано и автоматизировано развертывание HDFS-кластера, включающего в себя 3 DataNode и обязательные для функционирования кластера сервисы: NameNode, Secondary NameNode.

Развертывание, запуск, остановка и проверка кластера автоматизированы с помощью bash-скриптов. Все управляющие команды запускаются с edge-ноды `team-11-en`.

**Используемые версии:**

- Hadoop 3.4.2;
- Java 11.


## Архитектура кластера


| Узел | IP | Роль |
|---|---|---|
| `team-11-en` | `10.11.0.10` | Edge Node, SecondaryNameNode, DataNode |
| `team-11-nn` | `10.11.0.11` | NameNode |
| `team-11-00` | `10.11.0.12` | DataNode |
| `team-11-01` | `10.11.0.13` | DataNode |

# Назначение файлов

## `env.sh`

Содержит общие параметры кластера:

- имя NameNode;
- имя SecondaryNameNode;
- список DataNode;
- список всех узлов;
- SSH-пользователя;
- параметры SSH-подключения.

Благодаря этому адреса и имена узлов не дублируются во всех остальных скриптах.

Остальные скрипты подключают параметры командой `source env.sh`


## `config/core-site.xml`

Содержит общие настройки Hadoop.

В частности, здесь задается адрес NameNode, через который клиент обращается к HDFS.

Например:

```xml
<property>
    <name>fs.defaultFS</name>
    <value>hdfs://team-11-nn:9000</value>
</property>
```

## `config/hdfs-site.xml`

Содержит настройки непосредственно HDFS, в нем задаются:

- каталог хранения метаданных NameNode;
- каталог хранения данных DataNode;
- коэффициент репликации;
- дополнительные параметры HDFS.

## `config/workers`

Содержит список узлов, выполняющих роль DataNode.

В нашем случае:

```text
team-11-en
team-11-00
team-11-01
```

# `deploy_all.sh` — скрипт автоматического развертывания кластера

Последовательно выполняет действия следующих скриптов:

```text
01_install_node.sh -> 02_configure_node.sh -> 03_format_namenode.sh ->
-> 04_start_cluster.sh -> 06_check_cluster.sh
```

Код для запуска:

```bash
ssh team@111.88.130.12
cd hdfs-hw1
./deploy_all.sh
```
---

# `01_install_node.sh`

Скрипт устанавливает и подготавливает Hadoop на одном узле.

Он выполняет следующие действия:

1. проверяет наличие Java;
2. при необходимости устанавливает Java 11;
3. устанавливает Hadoop 3.4.2;
4. создает необходимые каталоги;
5. задает переменные окружения;
6. настраивает разрешение hostname.

Скрипт выполняется непосредственно на целевом узле.


# `02_configure_node.sh`

Скрипт устанавливает конфигурацию Hadoop на одном узле.

Конфигурационные файлы из каталога `config/` передаются на узел и распаковываются в:

```text
/opt/hadoop/etc/hadoop
```

Также скрипт автоматически определяет установленную Java и записывает актуальный `JAVA_HOME` в `hadoop-env.sh`.


# `03_format_namenode.sh`

Скрипт выполняет первоначальное форматирование NameNode.

Команда:

```bash
hdfs namenode -format
```

создает начальную структуру и служебные метаданные новой HDFS.

Перед форматированием скрипт проверяет, что каталог NameNode пуст, чтобы исключить случайную потерю уже существующих метаданных. Обычно этот скрипт запускается только один раз при первом развертывании.


# `04_start_cluster.sh`

Скрипт запускает все необходимые HDFS-демоны на соответствующих узлах.

Запускаются:

```text
NameNode
SecondaryNameNode
3 DataNode
```

Каждый демон запускается отдельно через SSH командой `hdfs --daemon start`, поэтому SSH-доступ между внутренними узлами кластера не требуется.

После запуска скрипт делает паузу 15 секунд перед проверкой кластера, чтобы дать DataNode время на запуск и регистрацию в NameNode. Значение 15 секунд выбрано как **практический запас** и не является требованием Hadoop.

# `05_stop_cluster.sh`

Скрипт корректно останавливает все работающие HDFS-демоны.

Остановка не удаляет данные HDFS, поэтому после нее кластер можно снова запустить с помощью `04_start_cluster.sh`. Скрипт используется при перезапуске, изменении конфигурации или обслуживании кластера.

# `06_check_cluster.sh`

Скрипт проверяет работоспособность и целостность развернутого кластера.

Он проверяет:

- наличие трех Live DataNode;
- запущенные HDFS-демоны;
- отсутствие критических ошибок в логах;
- возможность записать файл в HDFS и прочитать его обратно.

Кластер считается успешно работающим, если NameNode видит три DataNode, в логах нет критических ошибок, а тестовая запись и чтение файла выполняются успешно.
