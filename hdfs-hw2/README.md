# ДЗ 2 — автоматизированное развертывание YARN и публикация веб-интерфейсов

В рамках домашнего задания реализовано и автоматизировано развертывание YARN на существующем HDFS-кластере. Запускаются ResourceManager, три NodeManager и JobHistoryServer. Второе ДЗ использует существующий кластер из [первого ДЗ](../hdfs-hw1/README.md) и общие параметры из `hdfs-hw1/env.sh`.

Веб-интерфейсы основных и вспомогательных демонов кластера доступны с внешнего компьютера через SSH-туннель к edge-ноде `team-11-en`.

**Используемые версии:**

- Hadoop 3.4.2;
- Java 11

## Архитектура кластера

| Узел | IP | Роль |
|---|---|---|
| `team-11-en` | `10.11.0.10` | Edge Node, SecondaryNameNode, DataNode |
| `team-11-nn` | `10.11.0.11` | NameNode, ResourceManager, NodeManager, JobHistoryServer |
| `team-11-00` | `10.11.0.12` | DataNode, NodeManager |
| `team-11-01` | `10.11.0.13` | DataNode, NodeManager |

ResourceManager распределяет ресурсы кластера между приложениями. NodeManager запускает контейнеры на своём узле и сообщает ResourceManager об их состоянии.

JobHistoryServer показывает историю завершённых MapReduce-заданий, сохранённую в HDFS.

# Назначение файлов

## `env.sh`

Подключает общие параметры из первого ДЗ:

- имя NameNode;
- имя SecondaryNameNode;
- список DataNode;
- список всех узлов;
- SSH-пользователя и ключ;
- путь к установленному Hadoop.

Дополнительно задаёт:

- имя edge-ноды;
- узел ResourceManager;
- узел JobHistoryServer;
- список NodeManager;
- каталог второго ДЗ в HDFS;
- переменные окружения компонентов Hadoop.

Остальные скрипты подключают параметры командой:

```bash
source env.sh
```

Скрипт также проверяет, что управляющие команды выполняются на `team-11-en`.

## `config/yarn-site.xml`

Содержит настройки YARN:

- адрес ResourceManager;
- каталоги локальных данных и логов NodeManager;
- доступные приложениям память и процессорные ресурсы;
- ограничения размера контейнеров;
- настройки сбора логов;
- вспомогательный сервис для MapReduce.

Например, узел ResourceManager задаётся следующим образом:

```xml
<property>
    <name>yarn.resourcemanager.hostname</name>
    <value>team-11-nn</value>
</property>
```

Каждый NodeManager предоставляет приложениям 1536 МБ памяти и два виртуальных процессорных ядра. Размер контейнера ограничен диапазоном от 512 до 1536 МБ.

## `config/mapred-site.xml`

Содержит настройки запуска MapReduce через YARN:

- используемую платформу выполнения;
- пути к библиотекам MapReduce;
- адреса JobHistoryServer;
- каталоги истории заданий в HDFS;
- каталог временных файлов приложений;
- ограничения памяти ApplicationMaster, map- и reduce-задач.

MapReduce используется для дополнительной проверки вычислений с помощью WordCount. Эта проверка запускается отдельно от основного развертывания.

## `config/hw2-env.sh`

Задаёт переменные окружения Hadoop и размер Java heap для:

- ResourceManager;
- NodeManager;
- JobHistoryServer.

Для каждого из этих демонов установлен heap 256 МБ. Это память самого демона, отдельно от памяти контейнеров приложений.

Файл подключается из `yarn-env.sh` и `mapred-env.sh` на узлах кластера. `JAVA_HOME` в нём не задаётся: путь к Java находится в `hadoop-env.sh`, настроенном в первом ДЗ.

## `config/resource-types.xml`

Содержит пустую конфигурацию дополнительных типов ресурсов:

```xml
<configuration/>
```

В нашем кластере дополнительные типы ресурсов не используются. Файл добавлен, чтобы клиент Hadoop не выводил сообщение об отсутствии `resource-types.xml`.

## `config/web-interfaces.tsv`

Содержит таблицу веб-интерфейсов. Столбцы разделены табуляцией.

Для каждого интерфейса указаны:

- идентификатор;
- название службы;
- имя узла;
- внутренний порт;
- порт на edge-ноде;
- путь к веб-странице.

Эту таблицу используют скрипты публикации, проверки и открытия клиентского SSH-туннеля.

## `.gitignore`

Задаёт правила исключения отчётов, временных файлов редактора и кэша Python из новых добавлений в Git. Уже отслеживаемые файлы эти правила не исключают из репозитория.

# `deploy_yarn.sh` — скрипт автоматического развертывания YARN

Последовательно выполняет действия следующих скриптов:

```text
01_configure_yarn.sh -> 02_start_yarn.sh ->
03_start_historyserver.sh -> 04_publish_web.sh ->
05_check_yarn.sh
```

Перед запуском нужна работающая HDFS из первого ДЗ. Также должны быть настроены SSH-доступ с edge на все узлы и разрешение их имён.

Для внутренних подключений используется ключ:

```text
~/.ssh/team_internal
```

Ключи узлов должны находиться в `known_hosts`. Пользователь `team` должен иметь права на изменение конфигов Hadoop. Для публикации интерфейсов нужны пользовательский systemd и возможность включить `linger` через `sudo`, если он ещё не включён.

Код для запуска:

```bash
ssh team@111.88.130.12
cd ~/github-repo/hdfs-hw2
./deploy_yarn.sh
```

Перед настройкой скрипт проверяет, что HDFS вышла из safe mode.

Если HDFS остановлена, её можно запустить скриптом первого ДЗ:

```bash
cd ~/github-repo/hdfs-hw1
bash scripts/04_start_cluster.sh
```

Повторная установка Hadoop и форматирование NameNode во втором ДЗ не выполняются.

# `01_configure_yarn.sh`

Скрипт размещает конфигурацию второго ДЗ на всех четырёх узлах.

Он выполняет следующие действия:

1. проверяет наличие Hadoop и доступность каталога конфигурации для записи;
2. передаёт файлы из `config/` на узлы;
3. сравнивает их с установленными файлами;
4. устанавливает изменившиеся конфиги;
5. подключает `hw2-env.sh`;
6. создаёт локальные каталоги YARN;
7. создаёт необходимые каталоги в HDFS.

Конфигурационные файлы устанавливаются в:

```text
/opt/hadoop/etc/hadoop
```

Локальные данные и логи NodeManager находятся в:

```text
/opt/hadoop/data/yarn/local
/opt/hadoop/data/yarn/logs
```

Каталоги второго ДЗ в HDFS создаются внутри:

```text
/user/team/hdfs-hw2
```

Если конфигурация изменилась, а YARN или JobHistoryServer продолжают работать, скрипт прекращает выполнение. Перед установкой новых настроек нужно согласовать остановку служб.

# `02_start_yarn.sh`

Скрипт запускает:

```text
ResourceManager на team-11-nn
NodeManager на team-11-nn
NodeManager на team-11-00
NodeManager на team-11-01
```

Каждый демон запускается отдельно через SSH командами:

```bash
yarn --daemon start resourcemanager
yarn --daemon start nodemanager
```

Перед запуском проверяется состояние демона. Уже работающие службы повторно не запускаются.

После запуска скрипт ожидает доступности веб-интерфейса. При первом запуске возможны временные сообщения об отказе подключения: процессу Java нужно время, чтобы открыть порт. Проверка выполняет повторные попытки.

---

# `03_start_historyserver.sh`

Скрипт запускает JobHistoryServer на `team-11-nn`:

```bash
mapred --daemon start historyserver
```

Перед запуском проверяет состояние демона, затем ожидает доступности его веб-интерфейса на порту `19888`.

В интерфейсе можно просматривать историю завершённых MapReduce-заданий.

---

# `04_publish_web.sh`

Скрипт организует доступ к веб-интерфейсам через edge-ноду.

Он выполняет следующие действия:

1. проверяет доступность внутренних веб-интерфейсов;
2. читает список перенаправлений из `web-interfaces.tsv`;
3. создаёт пользовательский сервис SSH-туннеля;
4. включает его запуск через systemd;
5. обеспечивает работу сервиса после выхода пользователя из SSH.

Файл сервиса:

```text
~/.config/systemd/user/hdfs-hw2-web.service
```

Туннель на edge подключается к `team-11-nn`, через который доступны внутренние узлы. Каждому веб-интерфейсу выделяется отдельный локальный порт.

Порты на edge слушают `127.0.0.1`. Для доступа с внешнего компьютера используется дополнительный SSH-туннель.

Состояние сервиса можно проверить командой:

```bash
systemctl --user status hdfs-hw2-web.service
```

# `05_check_yarn.sh`

Скрипт проверяет работоспособность YARN, HDFS и опубликованных веб-интерфейсов.

Он проверяет:

- наличие трёх NodeManager в состоянии `RUNNING`;
- регистрацию ожидаемых узлов;
- наличие трёх живых DataNode;
- отсутствие недоступных DataNode;
- целостность HDFS;
- работу сервиса SSH-туннеля;
- доступность всех десяти веб-интерфейсов через edge.

Повторная проверка:

```bash
cd ~/github-repo/hdfs-hw2
bash scripts/05_check_yarn.sh
```

При успешном завершении выводится:

```text
Все проверки пройдены
```

Для сохранения вывода:

```bash
mkdir -p reports
set -o pipefail
bash scripts/05_check_yarn.sh 2>&1 | tee reports/check-yarn.txt
```

---

# `06_stop_yarn.sh`

Скрипт останавливает JobHistoryServer, NodeManager и ResourceManager.

Перед остановкой проверяет отсутствие незавершённых приложений. Для запуска нужен флаг подтверждения:

```bash
bash scripts/06_stop_yarn.sh --confirm
```

Перед остановкой следует договориться не отправлять новые задания.

Остановка не удаляет данные HDFS. HDFS-демоны продолжают работать.

Для последующего запуска можно снова выполнить:

```bash
./deploy_yarn.sh
```

# `07_check_mapreduce.sh`

Скрипт выполняет дополнительную проверку вычислений на YARN с помощью готового примера WordCount.

Он выполняет следующие действия:

1. создаёт небольшой текстовый файл;
2. загружает его в отдельный каталог HDFS;
3. запускает WordCount;
4. читает результат;
5. сравнивает его с ожидаемым;
6. проверяет наличие файла `_SUCCESS`.

Код для запуска:

```bash
bash scripts/07_check_mapreduce.sh
```

Ожидаемый результат:

```text
hadoop  2
hdfs    1
yarn    2
```

Каждый запуск использует новый каталог:

```text
/user/team/hdfs-hw2/checks/<время>-<pid>
```

Результаты сохраняются в HDFS, а скрипт выводит полный путь и команду для их чтения.

Выполнение клиента ограничено 240 секундами. Параметр `--foreground` позволяет прервать его через `Ctrl+C`, а `--kill-after=5s` завершает принудительно, если после тайм-аута клиент не остановился за пять секунд. Остановка клиента или его тайм-аут сами по себе не гарантируют отмену уже отправленного приложения YARN.

Этот скрипт не вызывается из `deploy_yarn.sh`.

# Открытие веб-интерфейсов с компьютера

Клиентские скрипты запускаются на компьютере пользователя. Для них нужны SSH-клиент, доступ к edge-ноде и личный SSH-ключ.

По умолчанию используется:

```text
~/.ssh/id_ed25519
```

Для Windows нужен также `curl.exe`, если используется режим проверки.

## `client/Open-HadoopWeb.ps1`

Открывает SSH-туннель из Windows.

Из папки `hdfs-hw2` на компьютере:

```powershell
powershell -ExecutionPolicy Bypass -File .\client\Open-HadoopWeb.ps1
```

При необходимости можно указать другой ключ:

```powershell
powershell -ExecutionPolicy Bypass -File .\client\Open-HadoopWeb.ps1 -KeyPath "C:\Users\Viktor\.ssh\id_ed25519"
```

При открытом туннеле проверка выполняется в другом терминале:

```powershell
powershell -ExecutionPolicy Bypass -File .\client\Open-HadoopWeb.ps1 -CheckOnly
```

## `client/open_web_tunnel.sh`

Открывает SSH-туннель из Linux или macOS:

```bash
bash client/open_web_tunnel.sh
```

Адрес edge и путь к ключу можно передать аргументами:

```bash
bash client/open_web_tunnel.sh 111.88.130.12 ~/.ssh/id_ed25519
```

Терминал с туннелем нужно оставить открытым. Для остановки используется `Ctrl+C`. Перед запуском следует закрыть старые туннели, занимающие те же порты.
